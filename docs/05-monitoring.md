## nvidia-smi 를 주기적으로 보려면 원격에서 무언가 돌아야 한다

**`nvidia-smi` 는 그 기계 안에서만 실행된다.** GPU 드라이버에 물어보는 명령이라 밖에서
호출할 방법이 없다. 그런데 우리는 원격 컨테이너에 들어갈 수 없다. `kubectl exec` 는 EKS 의
pod 에만 통하고, 원격은 RunPod 의 컨테이너다.

지금 원격에서 나오는 것은 **stdout 한 줄기뿐**이다. driver 가 그것을 중계한다.

방법이 셋이다.

| 방법 | 하는 일 | 대가 |
|---|---|---|
| **A. stdout 에 섞어 보낸다** | `run.sh` 가 배경에서 `nvidia-smi` 를 30 초마다 찍는다 | 로그가 지저분해진다. 학습 출력과 섞인다 |
| **B. 별도 줄로 표시한다** | 같되 `PACSRUN_GPU=<json>` 형식으로 찍고 서버가 골라낸다 | A 와 같은 부하, 로그는 깔끔 |
| **C. 8888 포트에 `/metrics` 를 붙인다** | fetch mode 의 HTTP 서버를 확장 | driver 와 wrapper 를 고쳐야 한다 |

**B 를 권한다.** `PACSRUN_ARTIFACT=` 와 같은 방식이고 이미 있는 통로를 쓴다. 새 포트도
새 인증도 필요 없다.

```bash
# run.sh 에 넣을 것
watch_gpu() {
  while true; do
    sleep 30
    echo "PACSRUN_GPU=$(nvidia-smi --query-gpu=utilization.gpu,memory.used,memory.total,temperature.gpu,power.draw \
                        --format=csv,noheader,nounits | tr -d ' ')"
  done
}
```

- 30 초에 한 줄이면 25 시간짜리 job 에 3,000 줄이다. 학습 로그가 35 만 줄인 것에 비하면
  무시할 수 있다.
- 서버가 그 줄만 골라내 시계열로 저장하고 UI 가 그린다.

## shell 접근은 미룬다

**결정: VM 을 빌리는 경우에 한해 나중에 한다.**

- **컨테이너만 빌리는 경우는 어렵다.** RunPod 은 `args` 가 image 의 CMD 를 덮어써서 sshd 가
  뜨지 않는다. 넣으려면 8888 포트 서버에 명령 실행을 추가해야 하는데, **그것은 원격에서
  임의 명령을 실행하는 통로**라 인증을 신중히 설계해야 한다.
- **VM 을 빌리는 경우(GCP, AWS)는 다르다.** 그쪽은 이미 k3s 를 얹으므로 `kubectl exec` 에
  해당하는 길이 있다.
- 지금은 로그와 GPU 지표로 충분하다고 본다. 필요해지면 그때 VM 경로부터 연다.
